Design tokens · v1 · 個人作品集

節制的、以排版建立層次的 token 系統

為長文技術 case study 設計：中性色承擔所有結構，單一主色只出現在可互動元素上，層次由字級、字重與留白建立。此頁只含 token 與元件基礎樣式，不含頁面版面。

正文 Inter · 程式碼 JetBrains Mono · 4px 間距基準 · WCAG AA 以上

04 — 圓角與邊框

理由：小圓角讀起來像工具而非消費品；三階足以區分「輸入元件 / 容器 / 浮層」。

--radius-sm 4px
Tag、Input、按鈕
--radius-md 8px
Card、Code block
--radius-lg 12px
浮層、命令面板
邊框規則：預設 1px solid --color-border；需要被指認的互動容器（Input、hover 中的 Card）用 --color-border-strong；焦點狀態不加粗邊框，改用 outline，避免版面位移。

05 — 陰影（僅 2 階）

理由：陰影只用來表達「脫離頁面平面」；同一平面上的分區一律用邊框，避免陰影堆疊造成視覺噪音。

--shadow-sm
下拉選單、tooltip
--shadow-md
對話框、命令面板
何時改用邊框：Card、程式碼區塊、表格、區塊分隔、任何不會浮起的元素 — 一律 0 陰影。深色模式的陰影不可見，改以 --color-border-strong 標示浮層。

06 — 斷點與內容寬度

理由：行寬以 ch 而非 px 控制，字級改變時行寬自動維持在 65–75 字元的閱讀區間。

Mobile
< 640px
左右邊距 20px，單欄，區塊間距 48px，行寬自然落在 40–50 字元。
Tablet
640 – 1023px
左右邊距 32px，內容最大寬 720px，正文行寬 68ch。
Desktop
≥ 1024px
內容最大寬 1120px，長文欄 68ch，側註可外掛於 1120 之內。
Measure
--measure-prose: 68ch
上限 75ch、下限 65ch；程式碼區塊可放寬到 1120px 全寬。
這一段的寬度就是 68ch 的實際樣子。把眼睛掃過一行的距離控制在這個範圍，讀者不需要重新尋找行首，長篇 case study 才撐得住十分鐘以上的閱讀。
